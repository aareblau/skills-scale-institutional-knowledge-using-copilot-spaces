# OctoAcme Project Management Documentation

Welcome to OctoAcme's centralized project management process documentation. This README serves as your entry point to understanding how OctoAcme runs projects, manages teams, and delivers value consistently across all cross-functional initiatives.

## Overview

OctoAcme follows a structured, customer-first approach to project delivery that emphasizes iterative delivery, clear ownership, data-informed decisions, and psychological safety. Our project management framework ensures that every team member—from developers to stakeholders—understands roles, processes, and expectations.

## Core Principles

- **Customer-first**: Prioritize customer value and usability in all decisions
- **Iterative delivery**: Deliver small, testable increments to gather feedback early
- **Clear ownership**: Each project has a named Project Manager (PM) and Product Lead responsible for success
- **Data-informed decisions**: Measure impact and iterate based on evidence
- **Psychological safety**: Encourage feedback, learning, and continuous improvement

## Project Lifecycle

OctoAcme projects follow a five-phase lifecycle:

1. **Initiation**: Validate business need, identify stakeholders, and establish high-level timeline
2. **Planning**: Break work into shippable increments, prioritize backlog, and define acceptance criteria
3. **Execution**: Build, test, review, and iterate with regular team synchronization
4. **Release**: Deploy to production, verify functionality, and announce to stakeholders
5. **Close & Retrospective**: Capture learnings, celebrate successes, and drive continuous improvement

## Key Artifacts at a Glance

Every OctoAcme project maintains these core artifacts:

- **Project Charter / One-pager** — Problem statement, goals, success metrics, stakeholders, timeline
- **Prioritized Backlog** — Ranked work items with acceptance criteria and estimates
- **Definition of Done (DoD)** — Shared agreement on what "complete" means
- **Risk Register** — Tracked risks with mitigation plans and status
- **Release Plan** — Milestones, dependencies, and deployment timeline
- **Retrospective Notes** — Learnings and action items for continuous improvement

## Communication Cadence

Consistent communication keeps teams aligned and enables rapid issue resolution:

- **Daily standups** (15 min) — Progress, blockers, and dependencies
- **Weekly PM + Product Manager sync** — Strategic alignment and risk review
- **Twice-weekly delivery standups** — Team-level execution updates
- **Monthly stakeholder updates** — Progress, wins, and anticipated milestones
- **Ad-hoc escalations** — Immediate attention for blocking issues

## Core Roles

- **Project Manager (PM)** — Coordinates delivery, manages schedules, risks, and communications
- **Product Manager (PdM)** — Defines outcomes, prioritizes the backlog, and measures success
- **Developers** — Implement features, collaborate on design, and maintain quality
- **QA/Testing** — Validate acceptance criteria and product quality
- **Stakeholders** — Provide business context, approvals, and strategic direction

See [Roles and Personas](octoacme-roles-and-personas.md) for detailed responsibilities.

## Getting Started

**New to OctoAcme?** Start here:
1. Read the [Project Management Overview](octoacme-project-management-overview.md) for a 10-minute orientation
2. Identify which project phase you're in
3. Refer to the specific guide for your phase using the links above
4. Check [Roles and Personas](octoacme-roles-and-personas.md) to understand your responsibilities

**Running a project?** Use this checklist:
- [ ] Complete Project One-pager during Initiation
- [ ] Hold Kickoff meeting and finalize plan during Planning
- [ ] Maintain project board and conduct daily standups during Execution
- [ ] Prepare release checklist and conduct smoke tests before Release
- [ ] Run retrospective and track action items after Close

**Looking for templates?** Process documents include:
- Project One-pager template (Initiation guide)
- Backlog item template (Planning guide)
- Weekly status template (Risk Management guide)
- Release notes template (Release guide)
- Action item template (Retrospective guide)
